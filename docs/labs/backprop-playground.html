How to use this in class

Start one step at a time. Any mode opens with three neurons in one hidden layer — small enough that every number on the diagram is readable. Walk the four buttons once and read the loss, the gradients, and the update.

Then show that capacity is a choice. On Turnout · 2 variables the true boundary is a curve, and three ReLU neurons can only bend a line a few times. Run 100, look at the map, then press + on the hidden layer and run again — each neuron buys another kink. The same story runs on A bend with one input, where you can see the kinks directly.

Then break it. Set λ to 1.0 and watch the loss diverge. On XOR, switch the hidden layer to linear and watch it stall dead at 0.25, predicting 0.50 for everything — lecture 2's point about linear separability, live. Press Backward twice without zeroing and watch the gradients double.

Then test it properly. 🎲 Random data draws a fresh sample from the same rule, so you can ask whether the model found the pattern or just memorised the points in front of it.

To reproduce the lecture's own numbers, pick Straight line · y = 2x and press − on the hidden layer until it disappears. That is the deck's single linear neuron; set w and b to 0 under "show every parameter" and a point at x = 1, y = 2 gives L = 4 with ∂L/∂w = ∂L/∂b = −4, exactly as on the slide.

What the numbers mean
  • Value in a node — the output of that neuron for the highlighted data point (after its activation).
  • Red number under a node — ∂L/∂(that value): how much the loss would change per unit change in it. This is "the gradient flowing in from the right" from the lecture.
  • Gradient of a parameter — negative means increase it to reduce the loss; positive means decrease it. The size says how strongly the loss responds.
  • The loss — the mean over every data point, so every gradient is the mean of its per-point gradients. The diagram shows one point at a time (click a row to change it); the numbers being minimised are the average.
  • The prediction map — a grid of test points, coloured by what the model predicts there, so it moves as the model learns. The large ringed markers are your data, coloured by their true y, so they never move. With three inputs the map is a slice: two variables on the axes, the third held at the value shown, and only the data points at that value are drawn.
  • 🎲 Random data — a fresh sample from the same underlying rule, never a different rule. Each mode has one fixed pattern behind it, which is what makes "did it learn?" a question worth asking.
Is this really the same algorithm as the lab?

Yes. The engine underneath this page is a direct translation of the Value class from Lab 4: every node stores data, grad, its children and the local derivative with respect to each child; backward() topologically sorts the graph, seeds grad = 1 at the loss, and walks it in reverse accumulating child.grad += local_grad × node.grad. Nothing is approximated.

Check these gradients numerically (under "show every parameter") is the lab's grad_check: it recomputes every gradient with a central finite difference, (L(θ+h) − L(θ−h)) / 2h, and reports the worst disagreement. It should be around 1e-10.
